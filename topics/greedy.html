Greedy

Make locally optimal choices at each step. Globally optimal for specific problem structures.

Technique Locally Optimal O(n)

Key Facts

  • Time: typically O(n) or O(n log n) — depends on whether sorting is needed
  • Space: O(1) — greedy solutions rarely need auxiliary storage
  • Greedy choice property: a locally optimal choice leads to a globally optimal solution
  • Optimal substructure: the optimal solution to the problem contains optimal solutions to subproblems
  • Correctness: always prove or verify — greedy does not always work

How Greedy Algorithms Work

A greedy algorithm makes the locally optimal choice at each step with the hope that this leads to a globally optimal solution. Unlike dynamic programming (which considers all possibilities), greedy commits to one choice and never looks back.

Greedy works when the problem has two properties: the greedy choice property (a local optimum can be chosen without reconsidering past choices) and optimal substructure (an optimal solution contains optimal solutions to its subproblems). The classic example is interval scheduling: always pick the interval that ends earliest, freeing up the most room for future intervals.

Greedy does not always work — 0/1 Knapsack looks greedy but requires DP because fractional choices are not allowed. Before applying greedy, either prove it works (exchange argument: show any solution that doesn't follow the greedy choice can be transformed into one that does, without getting worse) or test with counterexamples.

Many problems combine greedy with sorting: sort the input to create a natural order of decisions, then scan linearly making the greedy choice. This gives O(n log n) overall.

  • Sort first — most greedy problems require sorting to define the order of decisions.
  • Exchange argument — to prove greedy works, show swapping any non-greedy choice with the greedy one never makes things worse.
  • Greedy ≠ DP — if order of choices affects future possibilities, you likely need DP.
  • If you're unsure, try a small counterexample first. Greedy fails fast on counterexamples.

Code Templates

Python 
# ── Jump Game (greedy: track max reachable index) ─────────────
def can_jump(nums):
    max_reach = 0
    for i, jump in enumerate(nums):
        if i > max_reach:
            return False          # can't reach index i
        max_reach = max(max_reach, i + jump)
    return True

# ── Merge Intervals (sort + greedy merge) ─────────────────────
def merge(intervals):
    intervals.sort(key=lambda x: x[0])
    merged = [intervals[0]]
    for start, end in intervals[1:]:
        if start <= merged[-1][1]:
            merged[-1][1] = max(merged[-1][1], end)  # overlap → extend
        else:
            merged.append([start, end])              # no overlap → new
    return merged

# ── Interval Scheduling (greedy: pick earliest end time) ──────
def max_non_overlapping(intervals):
    intervals.sort(key=lambda x: x[1])   # sort by END time
    count, last_end = 0, float("-inf")
    for start, end in intervals:
        if start >= last_end:
            count    += 1
            last_end  = end
    return count
