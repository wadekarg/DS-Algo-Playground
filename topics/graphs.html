Graphs

Graphs model pairwise relationships between objects using vertices and edges. They underpin problems in networking, routing, social connections, and dependency resolution.

Data Structure BFS / DFS O(V + E)

Key Concepts

  • Adjacency List — O(V + E) space; preferred for sparse graphs. Each node maps to a list of its neighbours.
  • Adjacency Matrix — O(V²) space; O(1) edge lookup. Preferred when edges are dense or you need frequent edge queries.
  • BFS — Level-by-level traversal using a queue. Use for shortest path in unweighted graphs.
  • DFS — Depth-first using a stack (or recursion). Use for cycle detection, path existence, topological sort.
  • Visited set — Always track visited nodes to avoid infinite loops in cyclic graphs.
  • Union-Find — Efficient data structure for connectivity queries and cycle detection.

How Graphs Work

A graph is a set of nodes (vertices) connected by edges. Unlike trees, graphs can have cycles and nodes can have any number of connections. They model anything with pairwise relationships: cities and roads, people and friendships, tasks and dependencies.

The two most common representations are the adjacency list (a dict mapping each node to its neighbours — O(V+E) space, preferred for sparse graphs) and the adjacency matrix (a V×V 2D array — O(V²) space, good for dense graphs or when you need O(1) edge lookup).

BFS (Breadth-First Search) explores level by level using a queue. Use it when you need the shortest path in an unweighted graph. DFS (Depth-First Search) goes as deep as possible before backtracking, using a stack (or recursion). Use it for cycle detection, connected components, and topological sort.

Always track visited nodes in a set — without it, cycles will cause infinite loops. For grid problems, the "graph" is implicit: each cell is a node, and its 4 neighbours (up/down/left/right) are its edges.

  • Ask: directed or undirected? weighted or unweighted? Can there be cycles?
  • BFS = shortest path (unweighted). DFS = reachability, cycles, topo sort.
  • Grid problems are just graphs in disguise — treat each cell as a node.

Code Templates

Python 
from collections import deque

# ── BFS template ──────────────────────────────────────────────
def bfs(graph, start):
    visited = {start}
    queue   = deque([start])
    while queue:
        node = queue.popleft()
        for neighbour in graph[node]:
            if neighbour not in visited:
                visited.add(neighbour)
                queue.append(neighbour)

# ── DFS template (iterative) ──────────────────────────────────
def dfs(graph, start):
    visited = {start}
    stack   = [start]
    while stack:
        node = stack.pop()
        for neighbour in graph[node]:
            if neighbour not in visited:
                visited.add(neighbour)
                stack.append(neighbour)

# ── Grid BFS (number of islands pattern) ─────────────────────
def grid_bfs(grid, r, c, visited):
    ROWS, COLS = len(grid), len(grid[0])
    queue = deque([(r, c)])
    visited.add((r, c))
    while queue:
        row, col = queue.popleft()
        for dr, dc in [(1,0),(-1,0),(0,1),(0,-1)]:
            nr, nc = row+dr, col+dc
            if 0 <= nr < ROWS and 0 <= nc < COLS and (nr,nc) not in visited and grid[nr][nc] == "1":
                visited.add((nr, nc))
                queue.append((nr, nc))
